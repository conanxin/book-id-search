# P3｜Ambition Architect × BOOK-ID-SEARCH 对照试验（预注册）

Date: 2026-10-14. GitHub main pinned to `8c9d3383b02e08e98b595dc58b76f3f93f7e1913`. This protocol was prepared **before any task A/B inference**. Model smoke `smoke.txt` only tested whether the runtime answered a trivial JSON question and does not count as experimental data.

## Hypothesis and scope

Does an explicit **Altitude+Depth+Range+Verifiability+Stewardship** instruction improve the usefulness of a book-search diagnosis and rerank, relative to an ordinary instruction, with identical data and output structure? This is a small paired exploratory pilot, not a randomized or representative causal experiment. The selected case types are intentionally contrasting; "case count" does not represent independent model calls.

## Immutable inputs

Frozen S31 v1.1 `cases.json`, `qrels.tsv`, `baseline-current.json` from existing repository. Do not edit any frozen file. Each model sees only **10 ordered candidates** with public ID, title, author, publisher, year and query; it never receives qrel grade, baseline/candidate metric values, historical candidate B2, or ground-truth diagnosis.

Preselected eight case IDs, split into two balanced batches (each 4 cases):
- Batch 1: `edition-choice-02`, `edition-choice-05`, `exact-natural-02`, `exact-natural-06`.
- Batch 2: `edition-choice-01`, `edition-choice-06`, `exact-natural-03`, `exact-natural-10`.

Selection intentionally spans search-result candidate gaps, usable-but-poor rankings, and apparently healthy results. Exact A and B prompts and input order are generated by `pilot.py prepare`, with SHA256 pinned in `preregistration.json`. **Prompt wording, outputs, and grading rule must not be modified after running.**

## Treatment and model conditions

- Same model in all arms: local Hermes CLI → provider `minimax-cn`, model `MiniMax-M3`, reasoning `low`.
- Same provided candidates and required JSON schema. Independent fresh single-query sessions; no previous conversation or user rules (`--ignore-rules`); no task-specific tools should be used (`-t none`, no external lookup requested, max turns 1), CLI timeout 150s, per-run agent budget 120s.
- Both arms must return each case: one of 4 diagnostic labels, exactly the same 10 candidate IDs in proposed order, one minimal next action, and one limitation.
- A: generic improve-search-quality instruction. B: high-level user outcome, bibliographic methods and competing hypotheses, explicit evidence and effort boundaries.
- Pre-fixed run sequence: `batch1_A → batch1_B → batch2_B → batch2_A`. The reversed order in batch 2 reduces (but does not eliminate) simple position confounding.
- The model may produce invalid JSON or run failures: record raw outputs and mark invalid instead of silently repairing or retrying. Model decisions are not automatically edits to the search implementation.

## External judge (kept hidden from the model)

The frozen QREL grades act as independent human-adjudicated labels for these candidates. Diagnose type by a **mechanical operational proxy**:
- `candidate_gap`: all 10 frozen grades are zero.
- `healthy`: rank-1 frozen grade is 3.
- `rank_order`: at least one frozen candidate has grade above zero and rank-1 grade is below 3.
- `uncertain`: optional model abstention, counted as not matching proxy diagnosis.

This operational proxy is **not a ground truth about full 5M-book corpus**. Basing diagnosis labels on QREL may undervalue reasonable uncertainty. Evaluate a candidate rerank using the same S31 nDCG@10 gain and IDCG over qrels (grades 0..3). If no graded-positive document exists in the input top10, any reordering cannot raise relevance. Do not call Hit@10 full-corpus Recall@10.

Primary descriptive indicators: per-case diagnosis agreement vs proxy, mean nDCG@10 improvement from fixed baseline, invalid JSON/candidate invention, arm elapsed time. Secondary qualitative review: whether next_action realistically addresses retrieval vs ranking and respects source uncertainty. No statistical significance claim, no claims about model-wide effectiveness, no generalization to historical research.

## Pass / stop rules

- **Execution ready** once all input prompt hashes match and same-model smoke succeeded.
- **Evaluable** only if every response passes schema and candidate-ID integrity checks. Partial results are still reported without forced aggregate comparisons.
- **Experiment complete** once both arms have valid outputs for all eight cases and the deterministic evaluator has emitted case-level results.
- **Effect not established** from a single small pilot, regardless of who scores higher; a future confirmatory run would require more cases, seeds and human-blind annotation.
