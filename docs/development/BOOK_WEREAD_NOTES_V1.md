# 同一本书里的微信读书记录

`task_id=BOOK_CENTERED_WEREAD_NOTES_V1` · 2026-10-11

## 本阶段的使用流程

在书目检索中找到一本书，使用 Google 登录后打开详情。书页沿用统一导航与内容区，在个人介绍、手工笔记、电子版外链旁增加“微信读书记录”：显示已经导入且确认关联到当前书目的划线、想法和书评。

记录默认查询全部时间、最新优先，每次加载20条；可以按类型筛选并继续加载。摘录正文、个人想法和记录日期分别呈现，保留合法的重复摘录。空列表、正在读取和读取失败有不同提示，失败后可重试。

“在微信读书中心查看本书记录”打开 `/weread?catalogId=<书目ID>`，自动读取本书首20条。中心明确显示本书筛选，笔记搜索、类型、时间、分页与导出仍限定该书；确认关联的记录提供返回书页的链接。只有用户清除本书筛选后，才切换到所有书的笔记，并保留手动加载全部笔记的入口。中心的阅读统计和阅读地图仍是账号总览。

这些记录属于已有的微信读书导入资料，浏览不会复制为手工笔记或自动加入“我的书籍”。本阶段复用现有 Google Owner 会话与既有数据，无需新增迁移或修改关联文件。

## 数据与边界

| 内容 | 现有来源／处理 |
| --- | --- |
| 书籍身份 | 公开目录 ID，沿用 `数字_12位数字` 格式 |
| 微信读书关联 | 既有 `weread-matches.confirmed.json` 的已确认匹配；不根据相似书名临时猜测 |
| 划线、想法、书评 | 已导入的 `weread-notes.snapshot.json`，由现有 private notes 服务筛选 |
| 查询 | `GET /api/private/weread/notes?catalogId=…&matchedOnly=true&days=all&type=…&limit=20&offset=…` |
| 数量 | notes 响应的 `pageInfo.total`，覆盖映射到该目录书的所有来源记录；不以单条阅读状态的笔记数量代替 |
| 访问 | 沿用 Google 登录；只读请求不新增写权限或持久化副作用 |

客户端原先会忽略不合法的 `catalogId`，使原本想查询一本书的请求变为全部笔记。本阶段修正为：没有传入该字段时，允许中心的全部笔记查询；明确传入空值或非法值时，在发出请求前拒绝。单书专用函数始终固定 `catalogId` 和 `matchedOnly=true`，不允许分页或外部参数覆盖。

单书响应必须全部属于当前目录书、且已经确认匹配，混入其他书目或未匹配记录时整批拒绝显示。书页和中心在书目、筛选、登录会话变化时清除旧状态，并取消在途请求；即使底层请求忽略取消，迟到结果也不能覆盖当前书。导出全书笔记的分页请求复用同一单书路径，取消会传到实际网络请求。

中心同时修正了已有的搜索时序问题：点击搜索后使用新查询值，切换筛选后旧列表及临时 AI 摘要不再用于下一页、导出或阅读主题。当前功能不提供原平台深链，因为现有公开给浏览器的数据不包含可靠的微信读书原文定位信息。

## 验证方式

沿用 `corepack pnpm install --frozen-lockfile`。定向检查覆盖客户端、书页记录组件、中心筛选与登录路径；API/Web 分别构建。

现有 Book library 工作流复用 disposable PostgreSQL16、受限应用角色及签名 Google 会话，继续执行第一批书籍内容浏览器旅程，并加入同书微信读书流程。微信读书夹具使用两本合成目录书、合成导入文件和真实的既有筛选服务；具体测试数量、源码身份、当前 CI 和浏览器报告统一记录在 [PR #72](https://github.com/conanxin/book-id-search/pull/72)。实际 Google OAuth、用户私有微信读书数据同步及腾讯云上线是不同的验证范围。

## 后续开发

下一阶段先建立持久化的人工关联确认／修正，明确人工修正与后续离线导入之间的优先级，避免下次导入覆盖已确认结果。然后加入基于书籍介绍、手工笔记和已关联微信读书记录的 AI 摘要、草稿及带来源问答，允许将结果明确保存为自己的内容。

本阶段追加在书籍内容 Draft PR #72 内，第一批 API／数据库／统一 UI 仍是基础。合并和发布状态以 PR 与项目 CURRENT_STATE 为准；本阶段不改变腾讯云运行服务。
