# 我的书籍：从笔记关键词回到具体内容

`TASK_ID=BOOK_CENTERED_LIBRARY_CONTENT_SEARCH_V1` · 2026-10-11

接续 `be861ceab697b1292d9c3fe425792bd154c069e8` 与累计 [Draft PR #72](https://github.com/conanxin/book-id-search/pull/72)，完成“保存阅读资料后，下次能找到并打开”的使用流程。

## 为什么做这一批

原“我的书籍”只搜索书名、作者、出版社和介绍全文；个人笔记仅用于数量与“有笔记”筛选。关键词即使出现在已经保存的笔记中，也无法据此找回书籍。介绍命中后，书卡仍只展示固定前180字，无法看见后半段的实际命中内容。

本阶段把当前笔记纳入现有检索，在结果卡片中展示命中摘录，并提供打开具体笔记或介绍的入口。复用原页面、PostgreSQL与Google会话，没有增加搜索服务、AI调用、依赖或数据库迁移。

## 查询与摘录

- 沿用 `GET /api/private/s32/library` 的 `q`、`filter`、`page`、`limit`。书籍仍按最近整理时间和目录ID排序，数量与分页按书计算，多篇笔记命中不会复制书卡。
- 保留原书目信息／介绍搜索。笔记只读取本书关联的 `ACTIVE`、`BOOK_LIBRARY_NOTE` 及其 `current_revision_id` 对应标题／正文。旧修订、已移除笔记和专题研究笔记不参与当前结果。
- 保留大小写不敏感的字面量查询；`%`、`_` 不能充当通配符。无查询词时使用普通书籍列表，不读取笔记全文。
- 非空查询优先展示最近更新的命中笔记，同时间按笔记ID稳定选择；没有笔记命中时，若介绍匹配则展示介绍摘录。仅书目字段命中时保留普通书卡。
- 每本书最多返回一条个人内容命中。摘录围绕实际命中词，正文片段最多240个Unicode字符，必要时前后各加省略号；笔记标题命中可以摘标题。API不向列表返回整篇笔记或历史正文。

列表项目新增可选 `searchMatch`，旧响应缺少此字段仍可显示：

```ts
type LibrarySearchMatch =
  | { kind: "introduction"; excerpt: string }
  | { kind: "note"; noteId: string; noteTitle: string; excerpt: string };

// LibraryBookSummary / LibraryItem
searchMatch?: LibrarySearchMatch | null;
```

没有个人内容命中或没有查询词时为 `null`。书籍数量、笔记数量、资源数量和原介绍摘要保持原有含义。微信读书导入记录继续在其现有检索入口查找；用户明确保存为独立笔记的AI内容会自然参与本次笔记检索。

## 打开命中内容

结果卡片显示来源、实际摘录及“查看这篇笔记”或“查看介绍”。链接由客户端依据本条书籍与笔记ID构造，复用现有目标：

- 介绍：`/books/:bookId#library-introduction-heading`
- 笔记：`/books/:bookId#book-note-:noteId`

书页在当前书的个人内容异步加载完成后，定位并聚焦存在的目标。一般重新渲染或保存不重复滚动；新书、新片段和新会话分别处理。已移除的笔记不能使页面跳到另一部书的目标。Google登录的返回地址同时保留路径、查询与片段，刷新或登录后能继续回到相应内容。
