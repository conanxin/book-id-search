## 使用流程

Google Owner 登录后的书页由主内容和独立 AI 侧栏组成。主栏保存用户编辑的介绍、笔记和电子版本；AI 使用相同的颜色、按钮与阅读排版，结果仅在侧栏临时展示。

| 操作 | 输入资料 | 结果操作 |
| --- | --- | --- |
| 参考介绍 | 当前目录、已保存介绍、独立笔记、有效关联的微信读书记录 | 查看来源、复制结果与来源、清除结果 |
| 笔记摘要 | 同一本书的实际独立笔记和微信读书记录，目录及介绍提供背景 | 同上 |
| 资料问答 | 问题与当前书籍的同一组资料 | 同上 |

点击生成后显示只读 Markdown 结果及本次实际资料数量；每个引用可以定位到对应来源卡片，查看摘录并返回书籍或微信读书页面。来源较多时，页面说明选取数量及截断情况。笔记摘要没有可用笔记时直接提示资料不足，不调用模型。

“复制结果与来源”将正文、问题（问答模式）、生成时间及被引用资料的摘录复制到剪贴板。浏览器不支持或拒绝剪贴板时，提供只读文字框供用户手动复制；没有自动粘贴、保存为介绍或新建笔记的入口。来源卡片提供的内部摘要校验值和修订ID不作为面向用户的操作选项。

AI 组件只接收书目 ID，不接收个人内容的保存或重载回调。生成、复制、清除以及模式切换不写个人资料，也不改变主栏尚未保存的编辑文字。用户确需采用文字时，自行进入主栏的手工编辑器修改并保存；原有版本与冲突处理继续属于这些编辑器。此次修正不回填或恢复任何既有介绍。

宽屏右侧固定宽度侧栏随页面滚动，并在内容过长时独立滚动；1050px及以下用“打开 AI 助手”／“关闭 AI 助手”控制浮动面板。仅关闭面板保留当前结果，Escape可关闭并返回开关焦点。生成或复制等待期间，用户已经转去手工编辑时，迟到结果不会抢走输入焦点。

切书、切模式、更改问题、退出或更换Google会话会取消旧生成并丢弃迟到结果；复制请求的迟到反馈同样失效。结果不持久化，刷新页面会清空。普通书目检索仍可匿名使用。

## 服务与资料选择

复用现有 `AI_FEATURES_ENABLED`、MiniMax配置／客户端、Google Owner鉴权、PostgreSQL连接池和微信读书有效关联服务。没有新增模型账户、依赖或数据库迁移。

资料由服务端读取，不接受客户端注入的正文、来源ID或任意外链。有效微信读书关系继续遵循人工绑定／解除优先于导入匹配；关闭微信读书功能时仍可使用书籍介绍和独立笔记，并准确报告未启用。已配置的资料读取失败返回服务不可用，不假装成功生成。

| 限额 | 规则 |
| --- | --- |
| 来源总数 | 最多24项：目录1、介绍1、最近独立笔记8、最近微信读书记录14 |
| 摘录大小 | 目录最多1,000字符，其余单项最多4,000字符，合计最多24,000字符 |
| 选择方式 | 分别为独立笔记与微信读书保留预算，报告可用数、实际采用数、总字符及截断状态 |
| 问题 | 去除首尾空白后1–1,000字符；仅问答模式接受 |
| 模型调用 | 复用现有协议，最大3,500输出tokens、45秒超时 |
| 输出正文 | 最多8段，每段必须引用实际来源，合成正文最多12,000字符 |

来源正文清理无效控制字符及不完整Unicode；截断不拆开代理对。每项来源包含稳定的本次引用编号、类型、标签、站内链接、准确摘录、摘录SHA-256和当前独立笔记修订ID（其他类型为null）。数量表示本次读取的选择范围，不代表电子书全文已被解析。

**电子版本在此阶段仍是登记和打开外链。AI不会下载外链、读取远程PDF或声称读过书籍全文。** 问答根据已提供的资料回答；服务端约束引用存在及对应关系，不能据此保证模型对资料的理解一定正确。

## 接口合同

`POST /api/ai/books/:bookId/assistant`

请求为 `{action:"introduction"|"notes_summary"|"question", question?:string}`。书目ID沿用数字与12位数字组合；严格拒绝额外字段、无效ID、模式不匹配的问题。路由使用Google Owner、Origin、CSRF和16 KiB JSON请求限制。

响应包括：

- `bookId/action/question`：对应此次书籍和输入。
- `draft:{title,content}`：正文中的 `[S1]` 等引用由服务端生成。
- `sources[]:{id,kind,label,excerpt,href,contentHash,truncated,revisionId}`：本次实际资料。
- `citedSourceIds`：与正文引用一致的唯一来源集合。
- `context:{workspaceVersion,introductionIncluded,notesAvailable,notesIncluded,wereadAvailable,wereadIncluded,wereadEnabled,truncated,sourceChars}`。
- `source:"ai"|"insufficient_context"` 及 `generatedAt`。

模型只返回标题、带来源ID的段落和资料不足标记。服务端拒绝坏JSON、未知引用、无引用段落、自行插入的引用标记、额外字段或超限输出。客户端再次核对请求身份、站内同书链接、来源计数和引用集合；不缓存生成结果，不回显提供方或数据库错误细节。

无效输入400、目录不存在404、AI未启用／数据或鉴权配置不可用503、提供方失败或响应无效502；未登录或无效CSRF沿用现有鉴权响应。只有 `source:"ai"` 的有效结果提供复制操作。

## 验证与交付边界

定向验证覆盖只读结果与完整来源复制、剪贴板降级、无个人内容 API 调用、主栏未保存文字与焦点保留、登录／会话和迟到响应隔离。既有后端资料范围、人工关联、空资料、引用与CSRF合同不变。

现有 Book library CI 使用PostgreSQL16、受限应用角色、真实签名的合成Owner会话及Chromium。两条AI旅程验证连续生成／复制／清除期间零library写请求，并用独立数据库连接核对原介绍、笔记及另一书籍保持不变；同时保留主栏两个未保存编辑器，最后只经各自手工保存按钮写入。另测书籍切换、取消、退出及桌面／手机布局。模型响应是注入的确定性测试响应，不能据此表述真实Google交互登录、MiniMax连通性或回答质量验收。

桌面与手机视觉检查使用合成资料。当前源码身份、最终测试数量、精确提交CI结果与截图说明统一记录在本次修复PR，避免把PR #72的先前结果当作本次验证。

PR #72的API与Web及003／004已按用户提供的发布回执上线。本修正仅需更新Web，不改API、模型配置、数据库或已保存内容，不重放003／004。经本次修复的单独合并／发布授权后，用原Web构建脚本注入既有Google公开Client ID，在现场完整Compose链中只替换Web镜像并更新web服务。发布后刷新已打开的旧书页，加载新的AI侧栏。
