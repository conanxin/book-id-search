# 书页关联图书：排序与关系说明

`TASK_ID=BOOK_CENTERED_RELATED_DISCOVERY_V1` · 2026-10-11

接续 `c9a39cbaa46146d5c43b10c5955927ac8c05e12f` 与累计 [Draft PR #72](https://github.com/conanxin/book-id-search/pull/72)，完善原始产品需求中的“找到一本书，继续查看关联图书”。

## 改动目的

原书页已有相关图书入口，但算法先收集ISBN、作者，再用出版社补足10条，最后才考虑书名。累计列表达到10条后，后续查询直接跳过。因此书名候选可能根本没有进入结果；只对旧列表重排不能解决。卡片也没有说明关联依据，查询未完成时会短暂显示“暂无相关图书”。

本阶段分别读取各字段候选，再统一排序、去重及截取，并在共用书籍卡片中呈现关系说明。界面继续使用书籍工作台的卡片、按钮与绿色样式。

## 关联依据

| 优先顺序 | 依据 | 展示含义 |
| --- | --- | --- |
| 1 | `same_isbn` | 两条书目的ISBN字段规范化后相同 |
| 2 | `same_title` | 书名字段规范化后相同 |
| 3 | `title_query` | 通过当前书名的限定字段检索进入候选 |
| 4 | `same_author` | 作者字段规范化后相同 |
| 5 | `author_query` | 通过作者字段检索进入候选，未据此声称作者完全相同 |
| 6 | `same_publisher` | 出版社字段相同，作为较弱的补充线索 |
| 7 | `publisher_query` | 通过出版社字段检索进入候选 |

候选排除当前书，按目录ID去重，保留最多两个最强依据，最终最多展示10本。ISBN关系只比较ISBN字段；不会把SSID或DXID数字命中当成相同ISBN。匹配依据用于帮助选择下一本要查看的书，不等同于作品、版本或全文主题已经确认。

## 接口与页面

沿用 `GET /api/books/:id/related` 和现有 Google Owner 中间件。原有 `total`、`items` 保留；响应增加当前源书 `sourceBookId`、`partial`、`unavailableFields`，每项增加 `relations: [{kind, label}]`。`total` 仅是本次有限采样后的去重候选数量，不是整个索引的全部相关书数。

缺少源书字段时不执行空查询。某类检索失败时保留其他已取得的候选并标记部分结果，允许重试；全部实际查询失败返回服务不可用。只有源书读取明确返回 `document_not_found` 才报告404；连接、超时或索引故障报告503，避免误称书不存在。

书页区分加载中、空结果、部分结果和失败。相关查询不阻塞当前书的介绍与笔记；切书后旧响应不能覆盖新书。正常搜索卡片的搜索命中标记继续使用原有 `match`，不会用它冒充书与书之间的关系。

本阶段只读取目录，没有AI调用、个人内容读取或保存动作，也没有新增依赖与数据库迁移。微信读书的“按笔记主题发现图书”是另一条既有流程，本次不混入该接口。

## 验证与实际范围

定向测试覆盖候选独立读取、出版社不挤占书名、ISBN字段核对、自身排除、去重与上限、模糊和精确标签、部分／全部失败。页面测试覆盖关系及链接、加载与重试、切书和Google会话。沿用现有 Book library 工作流及 API／Web 构建；浏览器夹具复用生产关联收集器，目录搜索使用合成数据，不能当作真实Meilisearch语义质量验证。

精确提交、测试数量、浏览器证据及最终状态统一记录在PR #72。当前开发环境仍无实际模型／数据库配置；本轮通过设备清单确认唯一登记的本地桌面设备离线，未启动Hermes或腾讯云会话。此前真实模型试跑仍待原有配置机器执行，本阶段不将它改记为通过。

累计候选的发布方式沿用[增量发布说明](../operations/BOOK_CENTERED_RELEASE.md)，仍需现场核对003／004及现有运行参数。本阶段没有合并、发布镜像或部署腾讯云。
