# 微信读书书籍关联管理

`task_id=BOOK_CENTERED_WEREAD_MANUAL_BINDING_V1` · 2026-10-11

## 使用流程

微信读书中心提供“管理书籍关联”，书籍详情提供“管理本书关联”。管理页 `/weread/bindings` 沿用统一页面框架和 Google Owner 登录；从书页进入时用 `catalogId` 限定当前书籍，同时提供查看全部来源书的入口。

以导入的微信读书来源书为单位，列出书名、作者、ISBN、记录数量、当前目录书和关联来源。支持按来源书名／作者／ISBN搜索，按全部、已关联、未关联或人工处理筛选及分页。展开来源书后搜索目录，核对候选的书名、作者、出版社、年份和ISBN，再明确确认关联或更换。

| 操作 | 保存后的行为 |
| --- | --- |
| 确认关联／更换 | 记录人工选择的目录书；后续导入中的匹配结果不会覆盖它 |
| 解除关联 | 记录人工解除状态；原微信读书记录保留，后续导入不会自行复连 |
| 恢复导入匹配 | 恢复继承当前导入结果；导入没有匹配时显示未关联，之后的导入仍可更新匹配 |

解除与恢复导入是不同操作。更换关联不会把微信读书记录复制成手工笔记，也不会改写用户对目录书保存的介绍、独立笔记或电子版外链。

另一页面修改同一来源书时，旧版本写入返回409。页面保留已选候选，允许读取最新关联、核对新的当前目录书，再明确确认；不会自动覆盖新结果。

## 持久化与导入优先级

原始书籍／笔记快照和 `weread-matches.confirmed.json` 继续是导入输入。confirmed文件由离线脚本重新生成，在线人工操作单独保存在现有 PostgreSQL 的 `core.weread_binding_overrides`，迁移为 `004_weread_binding_overrides.sql`；001、002和003保留原字节。

每个微信读书来源书保存一种人工模式：绑定指定目录、明确解除或继承导入；每次成功操作递增版本。恢复导入仍保留版本序列，避免删除覆盖后旧版本请求重新变成有效请求。

有效关系按来源书计算：有人工绑定则使用人工目录，有人工解除则保持未关联，否则使用最新导入的确认匹配。允许多个微信读书来源书指向同一本目录书；单书记录数量应聚合所有对应来源，不能因用目录ID做唯一键而丢失来源。

书页记录、笔记查询与导出、单书／批量状态、总览、趋势、阅读地图与年度回顾使用同一有效关系。源文件的缓存与人工覆盖分开，人工操作后下一次读取即使用数据库里的新结果。浏览器状态缓存会失效；已发出的旧请求不能重新填入过期标记。

没有配置现有数据库能力时，已导入内容可继续只读查看，管理页不能保存人工操作；已配置数据库但读取失败时返回服务不可用，不能静默恢复导入结果而撤销人工解除。

## 接口合同

全部管理接口位于 `/api/private/weread/bindings`，仅限现有 Google Owner 会话；PUT沿用Origin和CSRF检查。稳定的 `sourceKey` 是内部来源书ID的SHA-256摘要；管理响应提供页面需要的来源书元数据，不返回原始导入对象。

| 接口 | 请求及响应 |
| --- | --- |
| `GET /bindings` | `q`（最多200字）、`status=all/matched/unmatched/manual`、可选`catalogId`、`limit=1..100`（默认20）、`offset=0..1000000`；返回`{ok,items,pageInfo,writable}` |
| `GET /bindings/:sourceKey` | 返回`{ok,item,writable}`，用于单条读取及冲突后的重新核对 |
| `PUT /bindings/:sourceKey` | `{action:"bind",catalogId,expectedRevision}`，或`{action:"unbind"/"restore",expectedRevision}`；成功返回`{ok,item,writable:true}` |
| `GET /api/search` | 管理页复用现有书目搜索选择候选；普通书目检索仍保持匿名 |

`item`包含`sourceKey/title/author/isbn/notesCount/effectiveCatalog/importedCatalogId/origin/revision/updatedAt`。`origin`为`imported/manual/unlinked/none`。有效目录含`id/title/author/publisher/year/isbn/available`；即使目录元数据暂时不可读取，关联ID也保留，页面不会误报为解除。

后端在保存前核对来源书和目标目录存在。空或非法的明确书目范围不退化为全部列表。输入错误400、来源／目标不存在404、版本冲突409、持久服务不可用503。客户端不回显数据库或提供方的错误细节，切来源书／页面范围／Google会话时取消旧请求并丢弃迟到结果。

## 验证及交付

针对实际风险验证：人工选择跨读取和重建服务后保留；重新生成导入匹配不覆盖人工绑定或解除；恢复导入采用最新结果；多个来源聚合一致；陈旧版本不能覆盖；无登录或无CSRF不能写入；迟到响应不能恢复旧关联。

现有 Book library CI 继续使用 PostgreSQL16受限应用角色、真实签名Owner会话和合成目录／微信读书快照，加入人工管理的浏览器流程。测试不依赖用户私有资料。当前源码身份、测试数量、CI结果及浏览器证据统一记录在 [Draft PR #72](https://github.com/conanxin/book-id-search/pull/72)。

本阶段在同一开发候选上接续，不代表已合并或腾讯云已上线。后续整体发布需要配套应用003及004，并发布对应API和Web；本阶段只进行开发、验证和项目记录同步。

该后续由[本书 AI 助手 v1](BOOK_AI_ASSISTANT_V1.md)接续：基于同一书籍下的实际介绍、独立笔记和微信读书记录提供可保存的AI草稿、摘要与带来源问答。电子版本继续先支持登记和打开外链。
