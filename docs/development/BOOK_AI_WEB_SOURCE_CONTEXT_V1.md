## 语义边界

- 书目线索是对当前可见文字的机械比对，与 AI 选源是否成功、对问题是否相关是两个维度。
- 出现 ISBN、书名或作者文字，不意味着网页讨论的是目标书、版本已确认、内容可信、属于本书书评或已经阅读全文。
- 书名可能是人名，作者可能有多部作品。题名与作者共现不升级为“已核实本书”；缺少线索也不意味着无关。
- 保持原始来源顺序、ID、标题、URL、节选、日期、截断状态及读取令牌。不会隐藏未匹配来源或自动把结果改成资料不足。
- 请求仍只有 `{ question }` 和公开书目身份；私人介绍、笔记、微信读书记录及资源链接不进入提供方输入。

## API 合同

每个来源新增可选字段，旧响应缺失该字段继续有效：

```ts
bookClues?: {
  isbn: "matched" | "mixed" | "other_only" | "not_seen" | "unavailable";
  text: ("title" | "author")[];
}
```

新 API 为每个最终返回的来源计算该字段。`text` 只允许 title、author 的有序去重子集（title 在 author 之前），最多两项；不返回自由生成说明。字段存在时客户端严格校验对象键、枚举、顺序与类型，缺失时说明“书目线索未核对”。

| isbn 值 | 含义 | 页面文案 |
| --- | --- | --- |
| matched | 标题或节选出现目录中的单一 ISBN，未识别其他 ISBN | 出现本书 ISBN |
| mixed | 同时出现目标 ISBN 与其他 ISBN | 本书与其他 ISBN 同时出现 |
| other_only | 只识别到其他 ISBN | 只看到其他 ISBN |
| not_seen | 目录 ISBN 可比对，但当前标题和节选没有识别到 ISBN | 未见本书 ISBN |
| unavailable | 目录 ISBN 缺失，或不能识别为单一值 | 本书 ISBN 无法用于比对 |

ISBN 仅规范全半角、空白、连字符和 X 大小写；目录字段可有单一 ISBN / ISBN-10 / ISBN-13 标签前缀。不从任意解释文字或多值字段猜选一个值，不转换 ISBN-10 与 ISBN-13，也不宣称已完成校验码或出版物核验。来源中的十位形式需要明确 ISBN 标签，避免把其他编号当作 ISBN；978/979 开头的十三位形式可以裸出现。严格处理包含 Unicode 数字的边界，不把长编号的子串作为匹配。除 NFKC 自带的规范化外，不另行把其他数字文字转换成有效 ISBN；它们仍参与长编号边界判断。

只使用已经清洗和按预算截短、实际返回的 title 与 excerpt；两字段独立检查，不能拼接出不存在的 ISBN。重复出现同一 ISBN 不算多种 ISBN。书名、作者按完整目录文本比对，允许全半角、大小写及空白的规范化；不拆作者姓名、不删除著编角色或推断书名关系。空字段不匹配；非 CJK 字母、数字、组合符和下划线的词边界避免将短题名或作者匹配到其他单词内部，Han、Hiragana、Katakana、Hangul 保持文字片段匹配。判断层记录每个字段是否被截短，忽略触及被截字段末端的 ISBN 或文字候选，防止截断把长编号或单词变成完整匹配；这些内部标记不改变返回的来源原文或公开 schema。

## 来源选择与搜索

原 `source`、固定 `draft`、`citedSourceIds` 和 selector JSON 合同不变。模型仍只选择最多四个已有 ID，不输出事实综合或新的分类。服务端书目线索可进入 selector 输入，提示明确其只表示文字出现；有 ISBN 的商品页不能因此被当作研究资料，人物名出现不能确认是本书。

搜索提示优先使用 ISBN、书名和作者消除同名歧义，并围绕本次问题查找可核对资料。主题研究问题仍可以选择相关背景资料。保持原调用次数、期限、模型与令牌预算；没有自动续跑、自动重试或额外提供方请求。提示变化不等于检索质量已获证明，实际结果单独评阅。

## 页面与复制

选中来源和完整来源卡片都展示相同书目线索，并保留读取、原文依据、多来源对照入口。`data-book-clues` 使用 isbn 枚举，缺失字段为 legacy；这只用于稳定定位，不作为用户文案。

统一说明：

> 书目线索只核对当前标题和搜索节选中的文字，不代表已读全文、内容可信或属于本书书评。

题名或作者文字匹配分别补充“出现书名文字”“出现作者文字”。若所有所选来源都有新字段，但都没有 matched / mixed，显示：

> 所选资料尚缺可对应本书的 ISBN 线索；与本书的直接关联仍需核对。

此提示不改变资料是否充足或来源是否相关的状态。旧响应继续显示和复制，不能把缺字段推断成已检查且不匹配。复制使用同一受控说明，包含所复制来源的线索、适用的整体提示、原文和出处，不包含读取令牌。

`insufficient_sources` 有来源时新增“复制现有来源”，复制全部真实来源和原有不足说明；没有来源时不显示复制按钮。未挑选状态继续保留全部来源及“未自动挑选”说明。未保存个人编辑、会话和取消行为继续原有合同，不新增个人写入。

## 验证与回执

- 定向回归覆盖混合 ISBN、其他书目同人名、缺失/多值目录 ISBN、格式及数字边界、完整作者与非 CJK 文字边界、截短后不应出现的线索。
- 用 PR #82 已保存的实际搜索快照离线核对新线索，保留原有不同著作与混杂节选；不把期望写成“所有来源都属于本书”。
- 浏览器使用真实应用 HTTP、Owner/CSRF、一次性 PostgreSQL 和合成提供方来源，验证混合线索、无线索、旧响应、未挑选和不足时的读/复制。任何合成或兼容字段移除明确记录；不代记为真实提供方或真人 OAuth。
- 精确提交的 CI、构建、人工/独立内容复核及真实提供方结果分别写入 PR 和既有 Notion 项目页。原始失败不覆盖，任何内容相关性限制保持可见。
